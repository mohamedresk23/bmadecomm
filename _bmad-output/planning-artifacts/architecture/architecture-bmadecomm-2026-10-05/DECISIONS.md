# سجل قرارات المعمارية

التاريخ: 2026-10-05. الجمهور: المطورون وQA. النطاق: توثيق P0؛ لا إنشاء تطبيق أو تشغيل معاملات.

## ما اعتمده المستخدم

- المسار التشاركي؛ وثيقة قرارات ملزمة ومعها شرح تقني للمطورين وQA.
- Next.js وTypeScript وPostgreSQL، تطبيق واحد مقسّم إلى وحدات، وعامل خلفي يستخدم قواعد الأعمال نفسها.
- الهيكل المقترح src/app وmodules وcomponents وinfrastructure وshared، وdatabase/migrations وseeds وtests وdocs. الهيكل بذرة تنظيم، وليس تفويضًا لإنشاء ملفات تطبيق الآن.
- فصل واجهات المتجر والحساب والإدارة، وقواعد الأعمال عن صفحات وواجهات HTTP؛ تنسيق معاملات الطلب والحجز عند الحاجة.

## البدائل والسبب

عُرض Laravel مع React مقابل Next.js/TypeScript؛ اعتمد المستخدم الأخير. التطبيق الواحد يحافظ على معاملات PostgreSQL المشتركة ويقلل تشغيل الخدمات. لا حاجة مثبتة إلى microservices أو خادم API مستقل أو وسيط رسائل إضافي. عامل مستقل التشغيل من نفس المستودع مطلوب للمهام المتينة التي لا يصح ربطها بعمر طلب HTTP.

مصدر المنتج الوحيد هو PRD v2؛ UX يحدد السلوك وقيود العرض. افتراضات A-01–A-11 وأسئلة OQ-01–OQ-08 غير معتمدة تجاريًا. التفاصيل التقنية الموسومة PROPOSED توصيات للمراجعة؛ لا تتحول موافقة الحزمة إلى اعتماد مزود أو مدة جلسة أو سياسة ضريبة.

## حدود أدوات BMAD

uv غير متاح؛ محاولة resolver بتاريخ الجولة فشلت. Python الظاهر Windows Store alias وليس interpreter مثبتًا بحسب الفحص السابق. قُرئت إعدادات config/customize مباشرة. لا تُكتب .memlog.md يدويًا لأن المهارة تقصرها على memlog.py. هذا سجل مستقل بديل، ولا يدعي تنفيذ أداة الذاكرة أو lint_spine.py. يجري فحص ميكانيكي مكافئ متاح ومراجعات مستقلة، وتوثق حدود التحقق.

## قواعد المراجعة

AD-1 فقط يرث اعتماد الحزمة والحدود من المستخدم. AD-2 إلى AD-18 تثبت مشتقات اتساق المتطلبات؛ التفاصيل الاختيارية لا تحمل ADOPTED. لا قصة تتجاوز بوابة قرار منتج مفتوح يؤثرها. النسخة النهائية من العقد تعني اكتمال التصميم في نطاقه، لا جاهزية إطلاق أو موافقة على كل توصية.

## أثر المراجعات

- عُززت AD-4 بحالة استخدام الكوبون Reserved/Consumed/Released وإثبات أهلية العميل، مع إبقاء سياسة عدم إعادة الحد بعد القبول مقترحة كما في PRD §6.1.
- أضيف مخطط العلاقات وأمثلة request/response للعقود الحرجة؛ DDL/payload schema كاملة بوابة foundation مشتركة قبل القصص، لا تنفذ كل وحدة عقدًا مستقلاً.
- ظهر تعارض late Paid بعد تحرير آخر coupon claim واستهلاكه لطلب آخر. ثبتت قاعدة حفظ receipt دون تجاوز cap أو تعديل snapshot؛ تسوية الاستثناء قرار OQ-03/04، وتحظر القصص المالية المتأثرة قبل حسمه. لا يخترع العقد سياسة refund أو سحب الخصم.
- المقترحات الرقمية للأمان تتضمن upload، ولا تعني اعتماد A-11 أو OQ-06.
- اكتملت reconciliation وrubric وverification وadversarial، ثم structure/prose للشرح فقط. أُغلقت الثغرات الواضحة ووثقت gates الباقية. ملفات التصميم final في نطاق الوثائق؛ لا event memlog رسمي لأن أداته غير متاحة، ولا موافقة منتج/إطلاق مستنتجة.
