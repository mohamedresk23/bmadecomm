# تقرير التحقق — UX للمتجر الإلكتروني

- المصدر: [PRD v2](../../prds/prd-bmadecomm-v2-2026-10-05/prd.md).
- وثيقتا العقد: [DESIGN.md](DESIGN.md) و[EXPERIENCE.md](EXPERIENCE.md).
- تاريخ المراجعة: 2026-10-05.
- النطاق: مراجعة وثائق UX ومعايير الوصول، لا اختبار تطبيق أو موافقة إطلاق.

## الحكم المجمع

تعريف UX يغطي التنقل والمعلومات والشاشات والتدفقات والنماذج والجداول والفلاتر والحالات والتجاوب والصلاحيات والتفاعل، ويربط قراراته بالمصدر الوحيد. تغطي الوثيقة 32 سطح P0 و8 أسطح P1 مؤجلة و25 مكونًا مشتركًا، مع جميع FR-01–FR-60 في [coverage.md](coverage.md).

لا نتائج critical/high/medium مفتوحة ضمن نطاق المراجعة بعد التصحيحات. بقي تأجيل مرئي منخفض الأثر على تعريف السلوك: الهوية والألوان والخطوط وtokens غير محددة بطلب المستخدم. لا يُستخدم هذا الحكم كادعاء جهوزية بصرية أو اجتياز WCAG. افتراضات المنتج وقرارات السوق والمال والتوقيت والمزودين والصلاحيات التفصيلية موروثة من PRD وما زالت تحتاج اعتمادًا.

## أحكام فئات UX

| الفئة | الحكم | الدليل/الحد |
|---|---|---|
| Flow coverage | strong | UJ-1–UJ-5 بأسماء المصدر وخطوات وذروة وفشل؛ TF-1–TF-5 وPF-1–PF-4 تربط بقية الموارد. |
| Token completeness | adequate | لا token معلن بقيمة ناقصة ولا إحالة غير محلولة؛ الكائنات الفارغة تأجيل مرئي معتمد، وليست عقد تنفيذ نهائي. |
| Component coverage | strong | 25 اسمًا متطابقًا وعقدا عرض/سلوك لكل اسم. |
| State coverage | strong | الحالات F والحالات الخاصة تغطي surfaces P0 وP1 المؤجلة؛ Pending وCOD وstale وexpiry/permission موثقة. |
| Visual reference coverage | strong / محدود بالمراجع المتاحة | لا مراجع أو mockups مطلوبة في الجولة، ولا ملفات بصرية يتيمة؛ ليس تقييمًا لجماليات منفذة. |
| Bloat & overspecification | adequate | طول الوثائق يخدم المصفوفات المطلوبة؛ لم يضف provider schema أو framework أو مزايا جديدة. |
| Inheritance discipline | strong | المصدر والمسارات والمصطلحات والأولويات والافتراضات محفوظة، وكل قرار رئيسي مسند. |
| Shape fit | strong | أقسام الوثيقتين القياسية موجودة، مع نماذج وجداول وصلاحيات وتجاوب. |

## النتائج حسب الخطورة — الوضع النهائي

### Critical — 0

لا نتائج مفتوحة.

### High — 0

لا نتائج مفتوحة.

### Medium — 0

لا نتائج مفتوحة في تحرير UX. لا يشمل هذا العد قرارات PRD غير المعتمدة أو اختبار التطبيق المستقبلي.

### Low — 1

**Token completeness — الهوية المرئية مؤجلة عمدًا.** الموضع: DESIGN frontmatter وColors/Typography/Layout & Spacing. الأثر: لا يمكن اشتقاق palette/خطوط/مقاسات نهائية أو قياس تباين فعلي من هذه النسخة. المعالجة الحالية: الحفاظ على القيود فقط وعدم اختلاق قيم. الاستكمال لاحقًا عند اعتماد الهوية، قبل التنفيذ البصري النهائي.

## معالجات مراجعة الوصول والاتساق

| الملاحظة | المعالجة ومصدرها | الحالة |
|---|---|---|
| dialog focus/Escape/background | Accessibility Floor: دخول وإعادة focus، background غير تفاعلي، إغلاق لا يُفسر إلغاءً ماليًا؛ NFR-08 وFR-35/37. | عولج التعريف |
| authentication/paste | السماح باللصق ومدير كلمات المرور والإدخال المساعد، دون اختيار MFA جديد؛ NFR-08 وFR-02–04. | عولج التعريف |
| time limits | تفسير مهلة موثوقة وإعلان انتهاء وحفظ غير حساس وإعادة تحقق بلا Charge جديد؛ تقييم extension/exception في OQ-06 وفق المصدر. | التبعية موثقة؛ اعتماد السياسة والتحقق لاحقًا |
| reorder without dragging | نقل/اختيار ترتيب مكافئ بالسلوك، السحب اختياري؛ FR-08/11/15 وNFR-08. | عولج التعريف |
| zoom/spacing/focus/targets | معايير WCAG مشتقة للتكبير/reflow وتباعد النص وfocus غير محجوب وأهداف اللمس؛ NFR-08–09، دون اعتماد قيم typography. | عولج التعريف |
| دور منى في TF-3 | Store Owner وحده يمنح الأدوار؛ منى ترى ما يخول دورها فقط. | عولج |
| فشل دفع مقابل Refund | UJ-4 لا يسمح Refund بلا أموال مقبوضة، ويمنع محاولة جديدة قبل حسم السابقة. | عولج |
| P1 flow coverage | PF-1–PF-4 تغطي D-01–D-08 وتبقى خارج تنقل P0. | عولج |
| أسماء المكونات/المراجع/الصياغة | 25 اسمًا متطابقًا، coverage.md موحد، بادئة PRD للافتراضات، رسالة نتيجة إلغاء صحيحة. | عولج |

## التحقق اللاحق وحدود التسليم

تبقى visual identity/contrast، الاختبارات اليدوية بلوحة المفاتيح وقارئ الشاشة والمتصفحات والتكبير والجداول، وإمكانية الوصول لدى مزود الدفع والمصادقة، وأدلة قرار time limits، مرحلة لاحقة بعد التصميم/المعمارية والتنفيذ. المعيار هو [WCAG 2.2](https://www.w3.org/TR/WCAG22/) المحدد في NFR-08، وليس توسعًا في نطاق المنتج.

لم يُعدل prd.md أو تنشأ implementation code أو يُثبت مزود أو تبدأ مهارة معمارية/تنفيذ. docs بحالة draft تعكس الخيارات المؤجلة؛ طلب تعريف UX مكتمل ضمن نطاقه.
