الحكم المجمع

تعريف UX يغطي التنقل والمعلومات والشاشات والتدفقات والنماذج والجداول والفلاتر والحالات والتجاوب والصلاحيات والتفاعل، ويربط قراراته بالمصدر الوحيد. تغطي الوثيقة 32 سطح P0 و8 أسطح P1 مؤجلة و25 مكونًا مشتركًا، مع جميع FR-01–FR-60 في coverage.md.

لا نتائج critical/high/medium مفتوحة ضمن نطاق المراجعة بعد التصحيحات. بقي تأجيل مرئي منخفض الأثر على تعريف السلوك: الهوية والألوان والخطوط وtokens غير محددة بطلب المستخدم. لا يُستخدم هذا الحكم كادعاء جهوزية بصرية أو اجتياز WCAG. افتراضات المنتج وقرارات السوق والمال والتوقيت والمزودين والصلاحيات التفصيلية موروثة من PRD وما زالت تحتاج اعتمادًا.

التحقق اللاحق وحدود التسليم

تبقى visual identity/contrast، الاختبارات اليدوية بلوحة المفاتيح وقارئ الشاشة والمتصفحات والتكبير والجداول، وإمكانية الوصول لدى مزود الدفع والمصادقة، وأدلة قرار time limits، مرحلة لاحقة بعد التصميم/المعمارية والتنفيذ. المعيار هو WCAG 2.2 المحدد في NFR-08، وليس توسعًا في نطاق المنتج.

لم يُعدل prd.md أو تنشأ implementation code أو يُثبت مزود أو تبدأ مهارة معمارية/تنفيذ. docs بحالة draft تعكس الخيارات المؤجلة؛ طلب تعريف UX مكتمل ضمن نطاقه.

1. Flow coverage

strong

قورنت UJ-1…UJ-5 بأسماء المصدر حرفيًا: لكل رحلة بطل المصدر وخطوات مرقمة وذروة ومسار فشل. TF-1…TF-5 تكمل أعمال الهوية والكتالوج والإدارة والاستعادة والمقاييس؛ الشاشات S-01…S-16 وA-01…A-16 تصل إليها هذه التدفقات. القرار لا يوسع صلاحية الشخصية: تأسيس الموظفين يبقى للمالك، والاسترداد يبقى لمخول `orders.refund`.

فُحصت الإضافة المستهدفة PF-1…PF-4: تغطي D-01…D-08 وFR-47…FR-54 بأبطال من المصدر وخطوات مرقمة وذروة وفشل، وتبقى مشروطة بإطلاق P1 وعقوده وسياساته. TF-3 يميز الآن مسؤولية Store Owner عن رؤية منى وصلاحيتها كمديرة، دون منح صلاحية جديدة.

لا ملاحظات إضافية.

2. Token completeness

adequate

استُخرجت مفاتيح `colors/typography/rounded/spacing/components`: جميعها كائنات فارغة مقصودة. لا token مسمى بقيمة ناقصة، ولا إحالة `{path.to.token}` غير قابلة للحل. لذلك لا ينطبق عيب «لون معلن دون hex». DESIGN.md §Colors يحدد قيود التباين المستمدة من NFR-08 ولا يختار palette.

Findings

• low — تأجيل معتمد: لا يمكن استخدام DESIGN.md كعقد قيم بصرية نهائية أو إثبات التباين حتى اعتماد الهوية (frontmatter `visual_identity_status`؛ §Colors/Typography/Layout & Spacing). *Fix:* أكمل tokens وتحقق من التباين عند اعتماد الهوية لاحقًا؛ لا تملأها بقيم افتراضية الآن.

3. Component coverage

strong

تطابقت أسماء 25 مكونًا بين DESIGN.md §Components وEXPERIENCE.md §Component Patterns؛ لكل اسم anatomy/دلالة عرض وقاعدة سلوك فعلية ومصدر. مكونات P1 تعيد استخدام العقد المشترك ولا تضيف منظومة مكونات غير موثقة. حالات الرسوم والجداول والرفع والتأكيد والنتيجة المالية ليست أوصافًا من كلمة واحدة.

لا ملاحظات إضافية.

4. State coverage

strong

لكل سطح P0 الحالات المشتركة F: Default، cold-load/refresh، empty، success، error، disabled، focus، permission denied، network/timeout، session expired حيث تنطبق. الحالات المركبة تغطي فرق السعر والمخزون، إثبات الضيف، استعادة الهوية، Pending/late Paid، COD، stale، رفض الرفع، عودة البضاعة، Refund وفشل البريد. D-01…D-08 ترث F وتحدد الحالات الخاصة. القراءة عند انقطاع الشبكة لا تتضمن وعد offline writes جديدًا.

لا ملاحظات إضافية.

5. Visual reference coverage

strong

لا ملفات مراجع بصرية في imports/mockups/wireframes؛ عدم إنشاء mocks موثق لهذه الجولة النصية. لا orphan بصري ولا رابط لمشهد غير موجود، وحكم أسبقية الوثيقتين على المراجع مع أسبقية PRD موضح. هذا الحكم يخص تغطية المراجع المتاحة، وليس تقييم شكل واجهة منفذة.

لا ملاحظات إضافية.

6. Bloat & overspecification

adequate

الطول مبرر بتعدد أدوار الإدارة وبالمصفوفات المطلوبة من المستخدم. قواعد النماذج والجداول والحالات تقدم قرارات قابلة للاستخلاص، دون نسخ PRD كامل أو اختيار framework/palette أو حقول مزود أو عمليات متقدمة غير مطلوبة. التكرار حول Pending والصلاحيات والافتراضات يخدم المخاطر المختلفة في نقاط الاستخدام، لكنه يمكن اختصاره تحريرياً لاحقًا دون تغيير العقد.

لا ملاحظة تستدعي تعديلًا الآن.

7. Inheritance discipline

strong

`sources` في الوثيقتين يحل إلى PRD v2 نفسه؛ رابط الزوج و`coverage.md` يحلان داخل مساحة العمل. قرارات UX-01…UX-12 والشاشات والنماذج والجداول تحمل FR/NFR/AC أو أقسام المصدر. المصطلحات Order/Payment/Fulfillment وsnapshots والـRefund مستقلة كما في المصدر؛ القيم PRD A-01…A-11 وOQ-01…OQ-08 لا تصبح قرارات معتمدة. وحدات P1 لا تظهر في P0، والضيف صاحب إثبات تتبع للقراءة لا يحصل منه على صلاحية إرجاع أو إلغاء.

لا ملاحظات إضافية.

8. Shape fit

strong

DESIGN.md يتبع ترتيب الأقسام الثمانية القياسي. EXPERIENCE.md يتضمن Foundation، Information Architecture، Voice and Tone، Component Patterns، State Patterns، Interaction Primitives، Accessibility Floor، Key Flows، وResponsive & Platform. Forms وTables/Filters/Search وPermissions وOpen Items تلبي الطلب مباشرة؛ غياب Inspiration مبرر بغياب أي مرجع منتج أو هوية supplied.

لا ملاحظات إضافية.

مراجعة UX وإمكانية الوصول

التاريخ: 2026-10-05. النطاق: مراجعة تعريف السلوك في DESIGN.md وEXPERIENCE.md مقابل PRD v2، خصوصًا NFR-08/NFR-09 وAC-21. هذه مراجعة وثائق؛ لا يوجد تطبيق أو تصميم مرئي لاختبار اجتياز WCAG. درجات الخطورة هنا تخص نقص المواصفة، وليست عيوبًا مثبتة في تطبيق. PRD A-09/A-10/A-11 وOQ-06 تظل غير معتمدة؛ لا تختار هذه المراجعة هوية أو مزودًا أو مدة أو سياسة جديدة.

ما تدعمه الوثائق بالفعل

تغطي الوثائق labels الدائمة وربط الأخطاء بالحقول وملخصها؛ إعلان Loading والنتيجة وPending وتغير الإجمالي دون تغيير focus عند تحديث الخلفية؛ تفريق نجاح Order عن Paid؛ الصور البديلة والخيارات المسماة؛ بيانات الرسم المكافئة؛ رؤوس الجداول وعلاقات الخلايا والصفوف المكدسة؛ عدم الاعتماد على اللون أو hover؛ RTL مع عدم تشويه SKU والبريد والمرجع؛ ومنع كشف الحقول غير المخولة على الهاتف. لذلك لم تسجل هذه العناصر كنواقص.

حدود التحقق المتبقية

التباين والخطوط وأبعاد التحكم الفعلية غير قابلة للقياس قبل تصميم مرئي؛ تأجيل الهوية قرار المستخدم وليس سببًا لطلب palette الآن. سلوك لوحة المفاتيح وقارئ الشاشة، ترتيب focus، رسائل الحالة الفعلية، التكبير، والجداول المتجاوبة تحتاج اختبار تطبيق لاحقًا. تكامل الدفع المستضاف والمصادقة الخارجية يحتاجان اختبار رحلة كاملة بعد اختيار المزود. لا تصدر هذه المراجعة شهادة امتثال، ولا تفترض اعتماد NFR-08 أو حل قرارات OQ.

النتيجة: التعريف يغطي أساس الوصول، مع خمسة نواقص محددة أعلاه. تصحيحها في المواصفة أو توثيق تبعيتها المشروطة يسبق قصص التنفيذ المتأثرة؛ لا يتطلب كتابة كود الآن.
