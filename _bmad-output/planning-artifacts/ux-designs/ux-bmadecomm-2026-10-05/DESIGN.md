# DESIGN.md — قيود العرض

هذا المستند يحدد ما يمكن استخلاصه عن العرض من [PRD v2](../../prds/prd-bmadecomm-v2-2026-10-05/prd.md)، ويعمل مع [EXPERIENCE.md](EXPERIENCE.md) الذي يملك التنقل والسلوك. بناءً على اختيار المستخدم، لا توجد ألوان أو خطوط أو هوية مرئية معتمدة. كائنات tokens الفارغة مقصودة؛ لا تمثل palette افتراضية ولا تُستعمل كمصدر قيم لتنفيذ واجهة مكتملة.

متطلبات UX المحددة هنا قرارات عرض تفسر متطلبات المصدر، وليست إضافة وظائف أو تعديلات على PRD. تعليمات المصادر تعامل كمتطلبات المنتج ولا تمنح تفويضًا للبدء بالتنفيذ. عند التعارض مع أي مرجع بصري لاحق تكون وثيقتا DESIGN وEXPERIENCE مرجع UX، وتبقى قواعد المنتج ونطاقه في PRD أعلى منهما.

## Brand & Style

لا يحدد المصدر اسمًا تجاريًا نهائيًا أو tone مرئيًا أو مراجع إلهام أو نمط أيقونات. يستخدم اسم bmadecomm كاسم المشروع، لا كشعار معتمد. لا نضيف theme أو Dark Mode أو animation أو تصميمًا جاهزًا لمكتبة UI؛ لم يُختر framework أو UI system. المرجع: PRD §0، FR-42، واختيار المستخدم ترك الهوية غير محددة.

قيود العرض الأساسية: التمييز بين واجهة العميل ولوحة الإدارة، إظهار المنتج والسعر والنوع والتوفر بوضوح، فصل حالات الأموال والتجهيز عن حالة Order، وعدم إظهار وحدات P1 كأنها تعمل في P0. المرجع: FR-09، FR-12، FR-33–34، PRD §§4 و7، AC-19.

## Colors

اللون التجاري ولون الخلفية والنص والحدود ودرجات الحالات غير محددة. قبل اعتماد أي palette يُتحقق من تباين النص والعناصر اللازمة وفق الهدف المقترح NFR-08؛ لا يدل اللون وحده على نجاح الدفع أو نفاد المخزون أو خطأ الحقل.

تفسيرات معيار WCAG 2.2 AA المستهدف: تباين نص اعتيادي 4.5:1، ونص كبير 3:1 وفق تعريف المعيار، وعناصر واجهة/رسومات لازمة 3:1 ضمن نطاق المعيار واستثناءاته. هذه قيود مشتقة من NFR-08 وليست palette مختارة أو شهادة امتثال. أسماء الحالات والرموز/النص تكمل اللون. المرجع: NFR-08، FR-25–29، FR-30، [WCAG 2.2](https://www.w3.org/TR/WCAG22/).

## Typography

العائلة والحجم والوزن وline-height غير محددة. أدوار النص المطلوبة، دون تحديد قيم: عنوان الصفحة، عنوان القسم، النص الوصفي، label الحقل، القيمة، نص المساعدة، خطأ الحقل، حالة العملية، رقم/مبلغ الطلب، وخلايا الجداول. مصدر الأدوار: FR-09، FR-12، FR-21، FR-33، FR-41، NFR-08.

Labels مستقلة عن placeholders؛ النص لا يختفي بمجرد الكتابة، وحالات الأخطاء تقرأ مع الحقل. القيم النقدية تعرض العملة والدقة المعتمدة، والأرقام والـSKU والبريد والمراجع لا يُعكس ترتيب حروفها عند RTL. الاسم الكامل للمنتج ونوعه قابلان للقراءة في تفاصيل السلة والطلب ولو اقتضيا التفافًا. المرجع: FR-13، FR-19، FR-29، FR-33، FR-57، PRD A-01/A-04، NFR-08–09.

الحجم يستجيب لتكبير النص دون إخفاء أزرار Checkout أو حذف حقول مهمة؛ لا تتحول النصوص الجوهرية إلى صور. التفاصيل العددية للخطوط تُترك لاعتماد الهوية. المرجع: NFR-08، AC-21.

## Layout & Spacing

لا يوجد grid رقمي أو spacing scale أو عرض container مختار. التراكيب التالية قرارات UX مشتقة من المهمة، وليست متطلبات عددية جديدة.

| التركيب | ترتيب المعلومات المرئية | المصدر |
|---|---|---|
| الكتالوج والبحث | عنوان/استعلام، أدوات البحث والفلاتر والترتيب، عدد النتائج، المنتجات، التنقل بالصفحات. | FR-09–11 |
| تفاصيل المنتج | الصور ثم اسم المنتج والنوع والسعر والتوفر والكمية والفعل، يليها الوصف وسياسات الشحن والإرجاع. يمكن تجاور الصور والشراء عند اتساع الشاشة مع بقاء ترتيب القراءة. | FR-12–13، NFR-08–09 |
| السلة | بنود النوع/الكمية/السعر والتوفر، تغيرات تحتاج معالجة، Coupon وTotalsSummary، الانتقال لـCheckout. | FR-17–20 |
| Checkout | بيانات وعنوان، طرق شحن ودفع، Order Review، TotalsSummary وموافقة التغييرات، تقديم ونتيجة. لا ترتيب بصري يخفي الإجمالي قبل التأكيد. | FR-19، FR-21–29 |
| تفاصيل Order | الرقم والتاريخ، Order/Payment/Fulfillment منفصلة، بنود وعناوين وإجماليات، timeline؛ الإدارة تضيف أفعالًا مخولة وملاحظات وأثرًا. | FR-29، FR-33–39، FR-45 |
| قائمة إدارة | عنوان وفعل إنشاء مخول، فلاتر/بحث محدد، DataTable، Pagination؛ تفاصيل المورد منفصلة عن الأفعال المدمرة. | FR-14–15، FR-30، FR-33، FR-40، FR-58 |
| تعديل إدارة | أقسام بيانات ذات labels، تحقق مرتبط بالحقل، أفعال الحفظ/النشر المؤهلة، تنبيه stale/error قبل إعادة الإرسال. | FR-14–15، FR-34، FR-42، FR-56 |
| لوحة المؤشرات | فترة القياس، KPIBlock، SalesChart، الطلبات الحديثة والأكثر بيعًا وانخفاض المخزون. تبقى تعريفات الإيراد ظاهرة في المساعدة. | FR-41، PRD §10 |

عروض المصدر المقترحة: 320px هاتف، 768px لوحي، 1024px desktop، 1440px large desktop. يحدد EXPERIENCE كيفية الانتقال بينها؛ لا تعتمد الخطوات المالية على hover. تتكدس النماذج والإجماليات عند ضيق العرض، وتظل هوية الصف وأفعاله ومعلومات المال قابلة للوصول. المصدر NFR-09 وAC-21؛ هذه الحدود جزء من PRD A-11 الذي لم يعتمد بعد.

Arabic RTL مرتبط باعتماد PRD A-01 وليس سياسة لغة محسومة. إذا اختيرت لغة أخرى تُبدّل جهة التقدم والمحاذاة والمنطق الاتجاهي؛ لا تُعرض أداة تغيير لغة أو عملة P0 لأن المصدر لا يطلبها. مرجع FR-42 وPRD §4.4/A-01.

## Elevation & Depth

لا قيم shadows أو elevation معتمدة. الرسائل المرتبطة بنتيجة الدفع والمبالغ تبقى في المحتوى، ولا تختفي داخل notification عابرة. ConfirmationDialog يفصل القرار الخطير عن بقية الصفحة مع عنوان وملخص وفعل إلغاء ظاهر. المرجع: FR-24–29، FR-35–37، PRD §9 متطلبات الواجهة المشتركة، AC-07/14/15.

## Shapes

Corner radius وأشكال الأيقونات والبطاقات غير محددة. الحدود المرئية للحقول والجداول والحالات يجب أن تسمح بفهم المجموعة والمحتوى والفعل دون اعتماد على الزخرفة؛ الهدف يأتي من NFR-08، ولا يفرض شكلًا تجاريًا معينًا.

## Components

هذه قائمة المكونات المشتركة؛ سلوك كل اسم مطابق في EXPERIENCE.Component Patterns. لا تعد المكونات وظائف مستقلة إضافية. كل وصف يحدد anatomy ودلالة الحالة ويؤجل القيم المرئية غير المعتمدة.

| المكون | عقد العرض | مصدر PRD |
|---|---|---|
| Navigation | روابط مسماة وتجميعات واضحة ومؤشر موقع حالي؛ العميل منفصل عن الإدارة؛ غياب الوجهات غير المخولة أو غير المتاحة في الإصدار الحالي. | FR-06–09، FR-33، §4/8 |
| Breadcrumbs | المسار الحالي للكتالوج/المورد، بأسماء قابلة للقراءة دون نقل العميل إلى صفحات إدارة. | FR-15–16، NFR-08 |
| SearchFilters | labels وأداة ترتيب وعدد نتائج وقيم فلاتر ظاهرة مع وسيلة إزالة/مسح، لا فلاتر Brand/Rating P0. | FR-10–11، FR-33 |
| ProductCard | صورة واسم وسعر فعلي وSale Price/التوفر حيث تنطبق؛ لا rating/brand/wishlist قبل P1. | FR-09 |
| ProductGallery | صورة المنتج وصور إضافية مسماة؛ صورة النوع تظهر عند توفرها دون تغيير معنى اختيار النوع. | FR-12–13 |
| VariantSelector | خيارات النوع والعناصر غير المتاحة مميزة بالنص؛ النوع المختار مع السعر وSKU واضح. | FR-12–13 |
| QuantityControl | label وقيمة وأفعال زيادة/تقليل وإدخال يمكن الوصول إليه؛ حد التوفر مفسر. | FR-17، FR-32 |
| FormField | label وقيمة وحالة مطلوب ومساعدة وخطأ؛ focus ظاهر؛ لا لون خطأ وحده. | FR-01–05، FR-21–22، FR-58، NFR-08 |
| FormFeedback | رسالة نتيجة أو ملخص أخطاء بروابط/علاقة بالحقول، دون رسائل تكشف وجود الحساب. | FR-02–04، FR-58، NFR-08 |
| PrimaryAction | اسم فعل محدد، pending واضح، سبب تعطيل مقروء عند الحاجة؛ تأكيد Order لا يُسمى نجاح دفع. | FR-14، FR-23–29، §9 |
| SecondaryAction | فعل مساند واضح كالعودة أو الإلغاء أو معاينة المسودة؛ لا يوحي بقدرة غير مخولة. | FR-07–08، FR-14، §9 |
| StatusBadge | label حالة؛ في الطلب ثلاث مجموعات مسماة Order/Payment/Fulfillment، دون badge يخلط Paid وDelivered. | FR-25–26، FR-33–34، §7 |
| DataTable | عنوان/أسماء أعمدة وصفوف محددة الهوية وقيم كاملة وأفعال مسماة؛ الأعمدة الحساسة تخضع للدور. | FR-30، FR-33، FR-40–41، NFR-08 |
| Pagination | موضع الصفحة وتنقل مسمى؛ loading لا يختلق نتائج أو يحذف اختيار الفلاتر. | FR-09، FR-58 |
| DetailSection | عنوان قسم وقيم مسماة ومجموعات بيانات منفصلة؛ الخالي يختلف عن فشل التحميل؛ snapshots واضحة. | FR-05، FR-33، FR-55 |
| TotalsSummary | Subtotal/Discount/Shipping/Tax/Total والعملة وفق السياسة المعتمدة؛ تعديل سعر يحتاج عرض الفرق. | FR-19–20، §6، AC-10 |
| StatusTimeline | أحداث بتوقيت ومعنى؛ partial return ومهمة refund/late payment واضحة دون محو التاريخ. | FR-27–29، FR-33–38، §7 |
| ConfirmationDialog | عنوان الفعل والمورد وملخص أثره؛ Refund يوضح المبلغ والرصيد المتاح؛ إلغاء مستقل ظاهر. | FR-35–37، FR-56، §9 |
| FileUpload | وصف الأنواع/الحدود من الإعدادات المعتمدة، ملفات وحالة وخطأ لكل ملف؛ صورة غير صالحة لا تعرض كمنشورة. | FR-15، FR-56، NFR-09 |
| StatePanel | عنوان حالة وشرح وفعل متاح عند الحاجة؛ skeleton لا يبدو نتيجة نجاح أو رصيدًا حقيقيًا. | §9 متطلبات الواجهة، FR-60 |
| InlineNotice | إشعار قريب من السعر أو المخزون أو المنطقة أو المعاملة التي تغيرت؛ دائم إلى المعالجة في المسار المالي. | FR-18–19، FR-22، FR-27–28 |
| SessionNotice | انتهاء دخول أو إعادة إثبات مع وجهة آمنة؛ لا عرض أسرار أو بيانات عميل آخر. | FR-02، FR-06–07، §8.2 |
| KPIBlock | اسم المؤشر وقيمة وفترة/طريقة حساب أو رابط مساعد؛ unavailable لا تعرض zero. | FR-41، §10 |
| SalesChart | Revenue عبر الزمن للفترة المعتمدة، labels ووصف/بيانات مكافئة؛ لا اعتماد على اللون فقط. | FR-41، NFR-08 |
| NotificationList | نوع حدث ومورد ووقت وحالة معالجة/تسليم المصرح بها؛ لا بيانات حساسة لا يملكها الدور. | FR-43–45، FR-60 |

## Do's and Don'ts

| افعل | تجنب | مصدر |
|---|---|---|
| أظهر السعر النهائي وحالة المعاملة وتغيراتها قبل اتخاذ قرار. | إعلان Paid اعتمادًا على redirect أو refresh. | FR-19، FR-25–29 |
| حافظ على فرق Loading/Empty/Error/Zero. | استخدام صفر إيراد أو قائمة فارغة عند فشل التحميل. | FR-41، §9، FR-60 |
| اعرض سبب حدود الكمية أو المنع المرتبط بحالة المورد. | تمكين الشحن أو Refund من مجرد ظهور زر. | FR-07، FR-31–37 |
| اجعل الصور والحقول والجداول قابلة للفهم دون اللون أو hover. | اختيار هوية أو مكتبة أو نمط حركة دون مصدر/اعتماد. | NFR-08–09، اختيار المستخدم |
| احفظ مناطق الخطأ والإجماليات والتاريخ ضمن الصفحة عند الحاجة. | إخفاء معلومة دفع مهمة داخل toast يختفي. | FR-27–29، FR-33، FR-60 |
| اعتبر palette والخطوط والمقاسات المرئية غير المكتملة قرارًا لاحقًا. | تقديم كائنات tokens الفارغة كتطبيق UI جاهز. | اختيار المستخدم، PRD §0 |

لا mockups أو wireframes بصرية معتمدة في هذه الجولة؛ الوثيقتان تحددان السلوك والتركيب نصيًا. تأجيل الهوية اختيار صريح للمستخدم؛ استكمال tokens يسبق أي تنفيذ بصري نهائي، ولا يمنع استخراج تنقل وسلوك التطبيق من المصدر.
