- (direction) User requests implementation spec for Epic 03 — Store operational settings; no code implementation in this turn.
- (note) Sources: PRD v2 FR-22, FR-42, FR-55, FR-57, FR-58, FR-59, sections 4.4, 6, 7, 8.1, AC-11, AC-19; Architecture Spine AD-1, AD-2, AD-4, AD-9, AD-10, AD-14, AD-15, AD-16, AD-18; Solution Design content/settings submodule; UX Experience screen A-13 and Design components; Stories E03-01 to E03-04.
- (capability) CAP-1 intent: Store Owner manages store identity, locale, and currency with historical protection; success: Settings persisted and audited, currency change after first Order is rejected with 409 Conflict, logo upload uses F00-07 media pipeline.
- (capability) CAP-2 intent: Store Owner configures shipping zones and methods for fulfillment eligibility; success: Server rejects disabled method or unserviced address at checkout/quote, order address snapshots retain historical shipping terms.
- (capability) CAP-3 intent: Store Owner controls payment method availability without secret exposure; success: Disabled payment methods are rejected at order submission, server credentials are never exposed in admin/storefront DTOs.
- (capability) CAP-4 intent: Store Owner manages financial and operational policies as immutable versions; success: Policy edits create an incremented version row, historical orders and quotes preserve referenced version snapshot without mutation.
- (constraint) RBAC & Authorization: settings.read and settings.manage are strictly Owner-only (per approved matrix v2); all mutating endpoints require fresh staff session and CSRF/Origin validation.
- (decision) Module placement: settings is a submodule within content/settings per AD-2; policy read models are exported via typed contracts consumed by checkout and pricing.
- (decision) Database schema: additive tables store_settings, shipping_zones, shipping_zone_regions, shipping_methods, payment_method_configs, and operational_policy_versions with integer versioning and timestamps.
- (constraint) Currency lock rule: Changing operating currency is permanently blocked with 409 Conflict once any row exists in orders table (FR-42, AC-19); migration path is deferred outside MVP.
- (decision) Out of scope: Homepage editor (Epic 07), live online payment attempt/gateway transactions (Epic 11), carrier API integrations (manual per A-02), multi-currency switching, and customer-facing return portal (Epic 24).
