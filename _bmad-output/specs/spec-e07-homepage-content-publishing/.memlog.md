- (capability) CAP-1 (Homepage sections draft editor — E07-01): Authorized staff compose, enable/disable, and reorder approved homepage section types (hero, featured_categories, featured_products, best_sellers, new_arrivals, promotions) with validated catalog references and editorial ordering in homepage_drafts.
- (capability) CAP-2 (Catalog reference & section schema validation — E07-01): System validates that section types belong strictly to the approved FR-08 set, referenced product/category IDs exist in the catalog, duplicate references within a section are rejected, and every draft save is versioned (expectedRevision) and audited.
- (capability) CAP-3 (Authorized staff draft preview — E07-02): Authorized staff with content.read/content.manage preview the current homepage draft rendered through S-01 storefront components without exposing draft state to guests, customers, or shared caches, and with noindex headers/meta.
- (capability) CAP-4 (Immutable publication snapshot & cache invalidation — E07-03): Authorized staff with content.manage publish the current validated draft into an immutable homepage_publications snapshot, atomically recording the audit event and invalidating the public homepage cache.
- (capability) CAP-5 (Public storefront homepage rendering & live catalog filtering — E07-03): Shoppers visiting S-01 see only enabled sections from the latest homepage_publications snapshot, dynamically resolving referenced products and categories at render time so unpublished/archived products or inactive categories are automatically excluded without breaking the page.
- (capability) CAP-6 (Accessible RTL admin editor & keyboard reordering — E07-01..03): Staff manage sections and item ordering in Arabic RTL (A-12) using full keyboard/button reordering controls (WCAG 2.5.7) without drag-only dependencies, and shoppers browse S-01 responsively across 320/768/1024/1440px without P1 controls.
- (constraint) RBAC enforcement: Only staff holding content.read / content.manage (default: owner, marketing; or explicitly granted role) may read/modify drafts, access preview, or publish; customer and guest sessions receive 401/403.
- (constraint) Approved section types only (FR-08, UX-10): Only hero, featured_categories, featured_products, best_sellers, new_arrivals, and promotions are permitted; no general-purpose CMS blocks, arbitrary HTML/script injection, or P1 controls (Wishlist, Ratings, Brands).
- (constraint) Draft & preview isolation (AD-12, AC-19): Drafts and preview endpoints must return Cache-Control: private, no-store and X-Robots-Tag: noindex, nofollow; unpublished changes never appear on public S-01 before explicit publish.
- (constraint) Live catalog safety at render (FR-08, FR-14, AC-19): Even if a product was published when added to a section or when the homepage was published, if that product is currently draft or archived (or a category is inactive), public S-01 rendering must filter it out automatically.
- (constraint) Optimistic concurrency & audit (AD-15, FR-45): Draft updates and publish commands enforce expectedRevision (409 on stale write), CSRF/Origin validation, and write append-only audit_events within the same PostgreSQL transaction.
- (decision) Resolve E07-01 content schema gate using minimal, non-invented discriminated union section payloads derived strictly from FR-08/FR-11 and EXPERIENCE.md A-12 (sectionId, type, enabled, position, and catalog reference IDs / optional title/CTA target within store routes).
- (decision) Decouple E07-03 from full E06-01 catalog listing page by defining a focused public homepage catalog projection query in src/modules/content/homepage/ that resolves published products and active categories for S-01 cards without waiting for S-02 search/filter pagination.
- (assumption) A-01 (Single-store Arabic RTL baseline): Single singleton homepage draft row (key='default') and sequential immutable publication versions (version = 1..N) in PostgreSQL.
- (assumption) Best Sellers section fallback (epics.md E06/E07 contract): Until Epic 13 records delivered-minus-returned unit facts, best_sellers resolves published products ordered by stable tie-breaker (published_at DESC, id ASC) or remains empty if no published products exist, never fabricating sales counts.
- (question) OQ-08 / Content media scope: Does Hero/Promotions section in E07-01 reference existing published media IDs via F00-07 or stay reference-only (category/product links + heading text) until Marketing media upload scope in e02-permission-matrix-proposal.md is finalized?
