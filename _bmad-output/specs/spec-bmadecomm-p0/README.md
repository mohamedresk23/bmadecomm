# مواصفة النظام P0

النطاق الذي اختاره المستخدم: جميع ملاحم P0 العشرين، باستخدام PRD v2 والمعمارية وUX وسياق المشروع. لا SRS مستقل مفترض، ولا P1 تنفيذية.

| الملف | الاستخدام |
|---|---|
| [SPEC.md](SPEC.md) | الهدف والنطاق، 20 قدرة بمعرفات CAP ثابتة، القيود وغير الأهداف والنجاح والأسئلة المفتوحة. |
| [implementation-requirements.md](implementation-requirements.md) | قواعد الأعمال، الواجهة والخادم وتغييرات قاعدة البيانات والتحقق والصلاحيات وحالات التفاعل. |
| [api-contracts.md](api-contracts.md) | عقود DTO وHTTP وidempotency والعمليات لكل مجال، والأخطاء والقرارات التي تحتاج تثبيتًا. |
| [acceptance-and-tests.md](acceptance-and-tests.md) | 20 نتيجة قبول قدرة و12 اختبار حدود مشترك، وخطة أنواع الاختبارات وأدلة الجودة. |
| [dependencies-and-migrations.md](dependencies-and-migrations.md) | اعتماديات CAP والبوابات وملكية القرار وترتيب migrations والتوافق والاستعادة. |
| [verification.md](verification.md) | مراجعة الاتساق والحفظ، وحدود تشغيل أدوات BMAD والأدلة. |

يقرأ المستهلك SPEC وملفات companions كلها. adopted PRD/UX/architecture ما زالت تحمل قيمة تعاقدية ولم تُكرر بالكامل؛ P1 داخلها لا تدخل هذا النطاق. موافقة الحزمة والهيكل لا تعتمد افتراضات A/OQ أو مزودين أو هوية مرئية.

المواصفة draft لأن قرارات المنتج والعقود التفصيلية التابعة لم تعتمد بعد. الأسماء التقنية هنا مسودة عقد موحد قبل القصص، لا كود جاهز أو OpenAPI مثبتة. لا stories.yaml أو sprint-status أو حزم/ملفات تطبيق بهذه الجولة.

أداة memlog الرسمية غير قابلة للتشغيل في البيئة الحالية؛ لا .memlog.md مزيفة أو مكتوبة يدويًا. حالة الاشتقاق الاستثنائية مسجلة في SPEC والتقرير. عند استعادة الأداة يُهيأ log رسمي مع القرارات الحالية ومعرفات CAP-1–20 محفوظة، ثم يعاد الاشتقاق عبر bmad-spec؛ لا يعاد ترقيم القدرات.
